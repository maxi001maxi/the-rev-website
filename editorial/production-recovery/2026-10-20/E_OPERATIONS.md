# Ownerの日常操作と復旧手順

本候補のGAS/API導入が受入済みになるまでは、下記の自動進行を本番保証しない。

通常：候補を選択 → 必要な一次情報回答 → 最後にConsoleの本文・画像・公開前チェックを確認してPublish。Google投稿は別にOwnerが行う。

自動側：正式Queue作成、Writer/Editor、独立QC、証拠付きの保持修復、画像無料検査、上限内のOpenAI制作、画像QC、正式Draft同期、公開前Preflight。正常に通ればチャットで各段階を起動し直す必要はない。

停止時：

| 表示・停止 | 対応 |
|---|---|
| 本文の根拠不足 | 確認可能な一次資料またはOwner情報を追加。点数だけ上げない |
| 修正後QCも不合格 | 指摘を確認。既存本文と旧QCを保持し、無制限再試行をしない |
| API呼出が不確実 | 台帳のrequest ID/usageと成果物を照合。STARTEDを削除しない |
| 画像不合格 | 隔離実物を確認し、構図・素材・編集方式の原因を直す。不合格版をREADYにしない |
| 配信/同期失敗 | 合格した本文・画像を再利用し、同期から再開。新記事や画像を重複生成しない |
| 公開前チェック待ち | 必須条件をすべて確認。Draftが見えるだけで完了にしない |

重要：PRマージ、GAS bundle導入とproperty有効化、Vercel本番導入は別作業。それぞれcommit/hash/versionを記録し、合成受入→本番読取→対象1記事の限定受入の順に進める。Publishは引き続きOwnerだけ。
